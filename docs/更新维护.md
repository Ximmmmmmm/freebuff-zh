# 汉化维护说明

> 这一页只放两样东西：**出了新版本怎么做**、**出事了怎么查**。
> 历史事故的完整复盘看 `git log` 与 [CHANGELOG.md](../CHANGELOG.md)。

## 出了新版本：一条命令 + 三步人工

```bash
# 0. 先把 manifest.json 里的 targetVersion / packVersion 升到新版本 —— 顺序很重要，见下
node tools/update.sh          # 自动跑完七步体检并出报告（全文归档到 work/）
# 1. 按报告小结补词条 / 补丁
node tools/lint_dict.js       # 词典结构 / 占位符 / 半截模板键 / 模板残骸自检
# 2. 构建 + 装机
bash build.sh                 # 内含 lint 门禁 + 全命中 + 产物自检，不过会直接中止
bash apply.sh
# 3. 发布（给别人用才需要）
bash tools/release.sh
```

- **顺序**：`update.sh` 第 6 步的上游对差按 `work/pristine/` 里的版本号挑基线，`manifest.json` 没先升版本会把本版当成新版；同一步的回归闸门也会跳过与本机 `packVersion` 同名的包（防止自己跟自己比），版本没升就退回更早的包当基线。已经跑早了就手动补一次：`node tools/regress.js dist/hanhua-pack-<上一版>.zip output`。
- **手工等价步骤**（`update.sh` 就是把这些串起来，外加下面六道体检）：先 `node tools/remap.js "<装机目录>/resources/orchestrator/ui/assets/index-XXXX.js" --write` 迁移模板变量改名（输出里的 AMBIGUOUS 需要人工改名，`update.sh` 会在小结里点名）；remap 够不着的那批再用 `node tools/resituate.js --ui "<同上的英文原版 bundle>" --write` 找回现形态（能自动的写回，CONFIRM / GONE 交人工）；再 `node tools/apply.js "<同上那个 bundle>"` 看末尾的 MISSED 清单，新增文案翻好加进 `dict.json`、原文已不存在的删掉（留着会卡住构建）；最后 `bash build.sh && bash apply.sh`。
- `update.sh` 多出来的体检，每道对应下文同名小节：

| 步 | 体检 | 在盯什么 |
| --- | --- | --- |
| 0b | `missed_diagnose.js` | 词典条目够不够得着本版 UI bundle（解包前就报，并说清该往词典还是补丁补） |
| 1b | `resituate.js` | remap 之后仍够不着本版 bundle 的旧词条：找回现形态，能自动的（RELOCATE）写回，其余列 CONFIRM / GONE 交人工 |
| 2 | `ui_patch_status.js` | UI 行为补丁该保留 / 重维护 / 退场 |
| 2b | `patch_preflight.js` | 主进程补丁的锚点：行号漂移还是上游改写 |
| 5 | `mainscan.js` | 主进程 `electron/*.cjs` 里没译的界面文案（第六种） |
| 6 / 6b | `upstreamdiff.js`、`regress.js`、`uipos_gap.js`、`lint_collisions.js` | 上游新增文案、变回英文的静默回归、单词级文案盲区、字面量占用 |

### remap 够不着的旧词条：`resituate`

`remap.js` 只在**固定段逐字节还在**时才能迁移 template 词条；锚文本被改写、或同一锚命中多处（AMBIGUOUS）它就交回人工。`resituate.js` 接住这一批：拿**本版英文原版**（`build.sh` 登记的 `work/pristine/<版本>/` 或装机目录）逐条找回现形态——四个分区的形态不同，定位手段也不同：

| 分区 | 定位手段 | 结论 |
| --- | --- | --- |
| `template` / 含 `${…}` | 固定段当锚、插值当捕获组（三种捕获形态 + 固定段序列扫描兜底） | 唯一候选 → `RELOCATE`；多候选 → `CONFIRM` |
| `code` 片段 | 标识符抹成通配的骨架子串搜索（含插值内名字） | 唯一且稳定文本够长 → `RELOCATE`；多形态 → `CONFIRM` |
| `exact` / `pattern` | 完整字面量集合里按词级相似度找改写句 | 一律 `CONFIRM`（散文不自动写回） |
| 都没有 | — | `GONE`（上游疑似下线） |

`--write` 只写回 `RELOCATE`（与 remap 同级自证：新键必须在本版 bundle 里逐字节命中、译文插值随变量名同步）；`CONFIRM` / `GONE` 列清单交人工，`--prune-gone` 才删死词条——`update.sh` 的 1b 步**不会**替你删。给 `--electron <目录>` 时还会把「其实只在主进程」的条目单列成 `MAIN`，提醒写进 `patches/` 而不是当死词条删。退出码 0 / 1（有 CONFIRM / GONE）/ 2（输入不足）。

```bash
node tools/resituate.js --ui <本版英文原版 bundle|ui 目录> [--prev-ui <上一版>] [--electron <electron 目录>] [--write]
```

### 上游这一版新写了哪些文案：`upstreamdiff`

「本版要翻什么」不需要汉化包：拿**两版英文原版**对差即可。`build.sh` 每跑一次就把本版英文原版登记成快照 `work/pristine/<targetVersion>/`（这是全流程唯一手里正好拿着英文原版的地方），`update.sh` 第 6 步用 `--auto` 取最新两版跑一次。

```bash
node tools/upstreamdiff.js --auto                                # 用 work/pristine/ 里最新的两版
node tools/upstreamdiff.js <上一版英文原版> <本版英文原版>          # 也可显式给路径（bundle / ui / resources / 快照目录）
```

它与 `regress.js` 是**两个基线、两个视角**，恰好互补：

| 工具 | 基线 | 回答的问题 | 缺基线时 |
| --- | --- | --- | --- |
| `upstreamdiff.js` | 上一版英文原版 | 上游本版新增 / 改写 / 下线了哪些文案（= 待翻清单） | 用 `tools/pristine.js` 补一版（见下） |
| `regress.js` | 上一版汉化包 | 我们有没有把已译的句子弄回英文（静默回归） | 首次发布 / 离线时只能跳过 |

报告分三块：**新增文案**（按「词典未覆盖 / 已覆盖」分开，前者就是待办；登记表里登记过的单列一节带理由，不进待补翻也不拦退出码）、**疑似改写**（按词重合度配对，旧词条会落 MISSED）、**上一版下线**（对应词条可能已成死条目）。退出码 0 / 1（有待翻）/ 2（输入不足——只有一版基线时会打印补齐办法，不是静默跳过）。

### 上一版英文原版从哪来：`pristine`（快照仓库，可跨机器搬）

上一版原版在本机会被抹掉：装机目录那份被自动更新覆盖，Freebuff 的更新下载缓存里没有安装包（electron-updater 装完即删），临时目录只有**本版**的包且存活很短。所以快照被设计成一件**可以搬的东西**：

| 场景 | 做法 |
| --- | --- |
| 本机还留着原版（`hanhua-backup-*` / 未汉化的装机目录 / 已解包目录） | `node tools/pristine.js capture`（默认就是这个） |
| 手上有安装包（NSIS，需要 7-Zip；也可用图形界面解包后 `capture <解包目录>`） | `node tools/pristine.js capture --exe Freebuff-0.0.113-win-x64.exe` |
| 换了机器 / `work/` 被清过 | `node tools/pristine.js import <别人给的 pristine-x.y.z.json.gz>`，或直接 `node tools/pristine.js import --from-release 0.0.113` |

```bash
node tools/pristine.js list                 # 仓库里有哪些版本、本机还能掘到什么、逐文件校验过没过
node tools/pristine.js list --remote        # 顺带探官方发布源还有哪些版本的安装包（HEAD，不计 API 配额）
node tools/pristine.js export 0.0.113 --out dist   # 导出成单个 .json.gz（Node 内置 zlib，无外部依赖）
node tools/pristine.js publish              # 把本版快照附到 pack-v<版本> Release（release.sh 会自动做）
node tools/pristine.js path 0.0.114 --require-electron  # 给 shell 脚本用：打印可用快照目录（rc 1 = 没有）
```

- 快照里是 `ui/index.html` + 主 bundle + `electron/` 下的 `.cjs/.html`，正好是 `upstreamdiff` 与 `mainscan` 需要的全部。**它不是可构建的完整原版**（不含 `node_modules/` / `src/`），要构建仍得装一次 Freebuff；`list` 会把「只有 ui 部分」的快照标出来，那种只能用于对差、不能用于发布闸门。
- 官方发布源上的旧版安装包**永久可下载**（`list --remote` 会打出 URL），所以「上一版从哪来」永远有答案；卡住的往往是「本机有没有 7-Zip 解 NSIS」——没有时 `capture --exe` 会直接把三条替代办法列出来。
- 快照逐文件 sha1 校验：`list` 报 ✗ 就是真的缺件 / 内容对不上，`import` 也会当场拒收被改过的文件。

## 日常：Freebuff 更新把汉化冲掉之后

Freebuff 自带 electron-updater，更新会整体替换 `resources/app.asar` 与 `resources/orchestrator/ui/`，汉化随之丢失。

```bash
bash apply.sh           # 用仓库里现成的 output/ 重新装上中文
bash restore.sh         # 想退回英文原版
```

装了多开控制器（v1.8.17+）的话 `apply.sh` 这步不用手动做：它默认开启「自动恢复汉化」，在**打开控制器时** / 启动实例前 / 检测到装机版本变化时自动重应用，本地 `bash build.sh` 跑完也会自己发现新构建换上（`output/` 三处产物 mtime 连续 8 秒不再变化才算完整，构建中途的半成品不会被换上）；没有实例在跑时才动手，没有开关也不用点任何按钮。

- 首次 `apply.sh` 会把英文原版备份到 `resources/hanhua-backup-<时间戳>/`；之后重复 apply 不再重复备份（避免把汉化产物当成「原版」污染备份链）。
- 备份不会无限堆：控制器会把它收敛到最近 2 份**完整**的快照（更旧的、以及写了一半的都清掉），时机是每次应用之后与控制器启动时。`apply.sh` / `restore.sh` 本身不清理，命令行反复跑的话可以在控制器里开一次，或手动删旧的 `resources/hanhua-backup-*`。

## 每种静默失败长什么样、怎么查

### 第三种静默失败：译文「变回英文」

`remap.js` 是按「去掉 `${...}` 后的文字骨架」找对应位置的。同一句话在 bundle 里若有多种变体（变量名 / 表达式写法不同），两条词条可能被指到同一处、互相覆盖，剩下那处就变回英文——而 `build.sh` 依旧报 `all keys matched`（它只检查词典里的词条能否匹配到东西，被吃掉的词条已经不在词典里了）。

```bash
node tools/regress.js dist/hanhua-pack-0.0.101.zip output   # 上一版包 vs 本次构建
```

`update.sh` 第 6 步自动跑（基线取 dist/ 里最新的旧包，没有则取历史 `output-*/`），结果写进 `work/update-*.txt` 并汇总在末尾；`release.sh` 发布前自动跑（基线是 GitHub 上一版 Release 的包，自动下载解包），发现新增英文片段就**中止发布**，确认那些英文是有意保留时用 `--allow-english` 放行。

#### 已知误报（提取器会把它们当文案，现在都已自动拦下）

提取器（`regress` / `upstreamdiff` 共用）不写 JS 词法分析器：引号按重叠配对、模板按相邻反引号逐段取，因此会抽出三类不是文案的片段。判据逐步加在 `CODEISH` 里，依据都是「先量后改」——四份 bundle（两版原版 + 两版产物）实测每条判据只影响那几条：

1. **类型守卫写法**：`` ,message:D instanceof Error?D.message: `` 这类三元被跨引号配对出来（`instanceof` 已收进关键字组）；
2. **跨模板定界符的代码**：抽出的片段带**裸反引号**（自然文案不会出现它，出现就说明跨了模板定界符）或 **`void`**（压缩产物里的 `undefined`，与 `typeof` / `instanceof` 同类），例如 `` :Xt?` - -menu`:void 0, ``；
3. **夹在两个模板之间的属性表**：模板分段会把代码抽成 `:"Freebucks balance unavailable","data-tooltip":t?` 这种「前三十几个字符像正常英文」的片段，判据是**引号紧贴逗号 / 冒号**（`,"` 与 `"\s*:`；自然文案里逗号与引号之间总有空格）。注意带转义引号的库内部消息（如 `unknown protocol \" \"`）属于另一类，不能一刀切。

三条判据都不会让真文案从清单里消失：同一条字面量在字面量级通道里照旧抽到，`test_upstreamdiff.js` 第 16/17 组用例把「旧口径会放行它们」「旁边的真文案仍进待补翻」都钉住了。拿不准的片段可以回原版 bundle 里搜一下：命中处是对象字面量 / 表达式而不是引号包着的整句，就是误报。

### 第四种静默失败：`uipos` / `fieldscan` / `regress` 三家都看不见的英文

界面里仍在英文的字符串有三类藏身处，三家扫描器全都够不着：

- **`children:[cond?"A":"B"]` 数组里的三元分支**（例如 `"Community setup guide"`）：`uipos` 的 JSX 文本节点只认「整段就是一个字符串」的元素，`apply.js` 的 `pattern` 也只取锚点值表达式**第 0 层**的字面量——它们在 `[` 里面，是第 1 层；
- **模板插值内部的字面量**（`` `${$e.enabled?"Disable":"Enable"} ${$e.configKey}` ``）：`uipos` 把 `${…}` 整体当成一个占位符，压根不进插值；
- **函数默认值 / 赋值语句里的字符串**（`const IF="Changed during agent work"`）：不在任何界面属性锚点上。

`regress` 也抓不到（抹掉 `${…}` 后往往不足三个词）。`tools/blindscan.js` 专治这一类：拿**英文原版**与**构建产物**对差，凡是「原版与引号相邻、产物里原样还在」的片段就是没被词典碰过的残留（翻过的会变中文；升级时 minifier 改的是插值里的变量名，不动字面量本身）。

```bash
node tools/blindscan.js <英文原版 ui 目录> output/ui     # 人看：带原版上下文
node tools/blindscan.js <原版> output/ui --no-ctx        # 紧凑输出，便于 diff 两版报告
node tools/blindscan.js <原版> output/ui --words 1       # 连单字标签一起找（噪音大）
```

输出分两桶：「疑似文案」（多词 + 常见小词，先看这桶）与「其余」（短标签 / 术语 / 库内部 / 品牌词）。列表里本来就会混着 CodeMirror / shiki / React 的库内部文案，人工挑出应用自己的那几条即可；也可以拿两次运行的报告 diff——存量噪音不变，新增行就是这版新长的。

补的时候：整句唯一就用 `exact`；只在界面位置出现的短词放 `pattern`；`children` 数组 / 嵌套模板里的片段用 `code` 逐字片段钉住，**不要带压缩后的变量名**，否则下个版本会失配。这类历史遗留的补翻不影响「本版适配完成度」的判定：`regress` 的「新增 0 处」保证的是本版没把已译的弄回英文，对差查的是「从一开始就没译过」。

### 第五种静默失败：崩溃重启后那条回复永远不完成

这是仓库里第一处**不是翻译**的产物改动（`tools/apply_ui_code_patch.js`）。该文件现在承载两组补丁：本节这组 `stream-epoch`（崩溃重启后被打断的那一轮永远不结束）与另一组 `token-epoch`（换 launch id 之后写操作一直 403，见本节末尾）。

成因：orchestrator 每个新回合把流式序号 `live.seq` 从 0 重新计数，而渲染进程的流事件守卫是「序号不增就整条丢弃」（`finish` 也在闸前）；崩溃前本地那条回复带着旧的高序号（例如 42）压住一切，新进程的低序号增量连同 `finish` 全被丢掉——那条回复停在崩溃前的内容、`done` 永远不为真。composer 已解锁，看起来只是「卡住」，且**完全静默**；下一条消息新建 `streamSeq:0` 的消息后才自愈。

补丁是三处协同：重连分支给未 `done` 的消息打 `streamSeq:-1`（作废本地序号）→ 守卫对 `-1` 放行 → 合并规则对 `-1` 一律保留本地内容（硬崩溃时本地那条是唯一副本）。为什么不能走词典：这些改动落在表达式上（守卫条件、三元分支、对象展开），锚点里全是 minifier 起的短名字；`apply_ui_code_patch.js` 改用「属性名 + 字面量 + 结构」匹配、短名字经捕获组原样带回，所以改名不失配，但每条补丁**必须唯一命中**（0 处或 ≥2 处都中止构建）。

**每组缺陷各有自己的探针**（新增一组补丁时就该配一条，否则 `ui_patch_status.js` 会把它如实标成 `UNKNOWN`）：

```bash
# 手工取证（三个 rc：0 符合预期 / 1 不符 / 2 无法取证）
node tools/probe_stream_epoch.js <原版 bundle> --expect present   # 缺陷必须仍可复现
node tools/probe_stream_epoch.js <产物 bundle> --expect absent    # 缺陷必须已消除且守卫仍在
node tools/probe_token_epoch.js <原版 bundle> --expect present    # 同左，token-epoch 组
node tools/probe_token_epoch.js <产物 bundle> --expect absent     # 必须已自愈且非 403 不误伤
```

补丁的验收分三层，缺一层就可能是静默带病：**① 锚点唯一命中**（找到了不等于找到对的那处）→ **② 哨兵**（`postbuild.js` 证明我们插进去了；但它只是文本存在性，表达式被上游改写后变成空操作时哨兵照样在）→ **③ 行为取证**（把装机 bundle 里的相关纯函数原样抽出来跑一遍事故时序，判据是行为而不是文本）。`update.sh` 的 2/7 步在**构建之前**就把补丁还站不站得住问一遍，`build.sh` 末尾的 `postbuild` 再对产物做一次（`release.sh` 走同一条路）。

#### 上游自己修好了怎么办（补丁退场）

```bash
node tools/ui_patch_status.js                          # 不带参数：自动找本机英文原版（hanhua-backup-* 优先）
node tools/ui_patch_status.js <原版 bundle|ui 目录|resources 目录>
```

它按**缺陷**分组（一个缺陷可以对应多条协同补丁），两个维度判定：锚点还能不能套用 × 原版还能不能复现出缺陷。

| 锚点命中 | 原版缺陷 | 判定 | 该做什么 |
| --- | --- | --- | --- |
| 是 | 仍可复现 | `KEEP` | 无需操作 |
| 否 | 仍可复现 | `REWRITE` | 上游改写了代码，重新定位锚点 |
| 是 / 否 | 复现不出 | `RETIRE` | 上游自己修了，按它给出的清单退场 |
| 拿不到证据 | 拿不到证据 | `UNKNOWN` | 人工核对，**不要**据此删补丁 |

退出码 0/1/2/3 = 全部 `KEEP` / 有可退场 / 有需人工介入项（`REWRITE` 或原版路径不可用）/ 仅无法取证。`RETIRE` 时会打印按顺序的删除清单（补丁条目 → 探针与自测 → `postbuild` 的取证段 → 本工具的缺陷登记表 → `update.sh` 的 2/7 步 → CI 步骤 → 本节文档），照着删完跑一次 `bash tools/update.sh` 应当全绿。**护栏**：把已打补丁的产物传给它会被直接拒绝（rc 2）——产物里缺陷必然「复现不出」，据此删补丁正好是反的；想看产物是不是真修好了，用 `--expect absent` 的探针或 `postbuild` 的行为取证。

#### 探针的锚点要容忍上游「往后加东西」

探针按结构把函数原样抽出来，锚点写得太死就会在上游加一行时退化成 rc 2「无法取证」（`ui_patch_status` 随之报 `UNKNOWN`，补丁去留没人能判）。例如 `foldParts` 的锚点曾写死 `switch(x.type){case"text":…`，而上游在 `"text"` **之前**插了一个 `compaction` 分支；现在锚点允许任意数量的前置 `case`，自测第 6 组用例钉住这个容忍度。**rc 2 不是「缺陷没了」，是「这次没取证」**，别把它当成可以退场。

#### 同一文件里的第二组补丁：换 launch id 之后写操作一直 403 forbidden

渲染进程把「本机 orchestrator 的写入令牌」读一次就**永久缓存**（`preload.cjs` 的 `apiToken()` → bundle 里的取值函数），而这个 id 会变：orchestrator 崩溃重启就换一个。令牌作废之后**每个写操作**都被判 `403 {"error":"forbidden"}`——发消息 / 停止 / 编辑 / 改名，连**开新标签页**也算（那是一次 `POST /api/threads`），而只读功能照常，窗口不重载就一直坏下去。两条补丁协同：`token-cache-resettable` 给缓存加一个失效函数（`_hanhuaResetToken()`），`reset-and-retry-on-403` 在请求包装器拿到 **403** 时丢掉缓存、**立即用新令牌重发同一次请求**（只重试一次；网络失败 / 5xx 与令牌无关，不丢缓存也不重试）。于是连触发的那一次调用都是成功的，用户看不到那句 forbidden。

与主进程那条补丁的分工：`patches/electron-main.cjs.patch` 让「同一次应用会话内 id 不再变」，是**少出事故**；这里让渲染进程「哪怕令牌陈旧也自己换回来」，是**出了事故能自愈**。

上游改写了这段代码时（锚点匹配不上，`build.sh` 与 `update.sh` 会直接报 MISSED），在新 bundle 里重新定位同一处语义、更新 `find` / `apply` 即可。注入标识符统一带 `_hanhua` 前缀（避免撞 minifier 短名），**不要在补丁里引入英文文案**（`semantic_guard` 会拦）。

### 第六种静默失败：主进程（`electron/*.cjs`）里的英文

前面几种都是**界面**的：`uipos` / `fieldscan` / `blindscan` / `regress` 全都只看 UI bundle，而主进程的文案（原生对话框、菜单、`shell:openIn` 的报错、MCP 同意窗口）**历来靠手写补丁**（词典的 `exact` 只替换双引号字面量，而主进程这些多为单引号或模板字符串）。于是只要某条文案没被写进补丁，它就能在**每一版**都静静躺着。

```bash
node tools/mainscan.js <原版 electron 目录> <产物 electron 目录>
```

判据只有一条（与 `blindscan` 相同）：片段在**英文原版**里存在、在**产物**里原样还在 ⇒ 没被翻过；比较按文件进行，报告给 `main.cjs:495` 这样的位置与原版上下文。修好的标准不是「零英文」，而是**只剩「约定保留」这一桶**。

- `update.sh` 第 5/7 步只报告不拦脚本（迁移途中本就该先发现再补，结论进小结）；`release.sh` 的**闸门一**会拦发布：拿英文原版与待发布产物对差，有疑似漏翻即 `exit 1`，并打印补翻路径。补丁里漏翻或改回英文的，**CI 的闸一**在 PR 阶段就会拦下（`tools/ci_gates.sh`：拿快照 + 词典 + 补丁重建主进程镜像再对差，不必等到发布）；只有版本刚 bump、本版原版还没发布那一次，它跑在上一版替身上、只列差异不拦（见「CI 里跑什么」的近似模式）。
- 按惯例**保留英文**的类别（不是遗留，别拿去翻）：应用名与可执行文件（Visual Studio Code / Cursor / Zed / Windows Terminal / File Explorer / `Code.exe`…，产品名且用于探测匹配）、`Task Manager` / `Activity Monitor`、格式名（`Markdown`）、信号名（`SIGKILL` / `SIGTERM`）、键盘键名、CDP 协议方法名、`[orchestrator]` / `[updater]` 开头的控制台日志，以及 bridge 的 HTTP 错误码文本。这些都在 `mainscan.js` 的 `INTENTIONAL` 名单里**逐条登记过**（带理由）；往后决定保留英文的新类别也加进名单，否则每次适配都会重新报出来。
- **补丁必须是「原版(LF) + 词典」这一真实基线的 diff**（`build.sh` 就是这个状态上 `git apply`）。可靠做法是拿产物（词典 + 补丁后的 LF 文本）改好文案再与基线 `diff -u` 重新生成，别手抄 hunk。
- **每个补丁文件对应一组译文哨兵**，加进 `tools/postbuild.js` 的 `MAIN_SENTINELS`——哨兵是硬检查，能拦住「补丁只套了一半」。
- 改完跑一次 `bash build.sh`：补丁套不上会在「套用人工补丁」一步中止，哨兵缺失会在自检里报。

#### 同一个补丁文件里的非翻译改动：窗口按钮区跟丢界面配色

`patches/electron-main.cjs.patch` 除了译文，还承载一处**外观**修正——同一个颜色有两个来源：界面侧是 CSS 变量（`--chrome` 在 `:root[data-theme=light]` 里声明四次、**后一份生效**；`--tabbar-height` 以 `.app-workspace` 里那条 `48px` 为准），主进程侧 `electron/main.cjs` 的 `SHELL_THEMES` 是一张**影子表**（`dark/light.overlay` 与 `titleBarOverlay.height` 全写死），窗口右上角那三个系统按钮（— □ ×）只认这张表。上游换配色 / 压矮标签条时漏改影子表，按钮区就会露出一块颜色与高度都对不上的矩形。

改法是**让影子表去读界面**：补丁新增 `HANHUA_SHELL_COLORS`，从 `process.resourcesPath/orchestrator/ui/index.html` 的主 CSS 里按「同一选择器取最后一块」读出这两个变量，用它填 `overlay` 与 `height`（`paintWindows()` 主题切换时一并带上）。敢这么做的理由：**读不到就回落**（`fallback` 就是当前这组值，整段包在 `try/catch` 里，最坏等于上游原样）、**不依赖 minifier 起的名**（找的是 `:root` 选择器与变量名，属稳定对外契约）、**以后自动跟随**（上游再换配色不用重新适配）。验收与译文补丁同一套：`MAIN_SENTINELS` 加四条哨兵，并做过负面测试（把产物里的 `overlay: HANHUA_SHELL_COLORS.light,` 改回旧值，自检立刻报「缺少译文哨兵」并以 1 退出）。

**但哨兵只查「那行文本在不在」。** 0.0.154 就栽在这里：上游把最外层配色改成**转发**
（`:root[data-theme=light]{--shell-base:#e3e7e4; … --chrome:var(--shell-base)}`），旧实现把取到的字符串
`var(--shell-base)` 直接交给了 Electron —— 那不是颜色，按钮区于是回落成系统默认底色
（实测 `#f0f0f0`），与标签条 `#e3e7e4` 差 13 级；而 `overlay: HANHUA_SHELL_COLORS.light,` 这行一个字节
都没变，哨兵照旧全绿。浅色下的正确值恰好等于补丁的 `fallback`，所以它还「看起来像是对的」。两处配套加固：

- **值也要解到底**：取到 `var(--x)` 就顺着引用继续找（同一选择器的块从后往前，最多 6 层、防环），
  并要求结果匹配颜色字面量（`#hex` / `rgb()` / `hsl()`）；解不出、成环、不是颜色一律按「读不到」处理，
  回落 `fallback`（最坏等于上游写死值，不会比原版更糟）。
- **判据从「文本存在」换成「行为」**：`tools/probe_shell_colors.js` 把产物 `main.cjs` 里的那块**原样抽出来**
  跑一遍，再拿界面 CSS **独立**解一遍（两侧各写一遍、不复用补丁的代码），比对底色 / 图标色 / 高度；
  `build.sh` 走到 `tools/postbuild.js` 时会对产物跑它（rc 1 中止构建，rc 2 只警告）。自测
  `tools/test_probe_shell_colors.js` 的两条核心用例直接从补丁的**新增行**里拼块：修好的 rc 0、旧写法 rc 1
  ——补丁改坏了自测就红。

> 这类「上游自己改了一半」的外观问题，判据是同一个值在**两处**独立定义。找它的办法：把界面上可疑颜色 / 尺寸的 CSS 变量列出来，去主进程里 grep 同名语义的硬编码值。
>
> 写这类探针本身也有两个坑（都已踩过）：① 抽出来的块用的是 main.cjs **模块级**的 `fs` / `path`，
> 沙箱必须把这些名字一并注入——少了它块会进 `catch`、静默回落成写死值，探针就把「读不到 CSS」误报成
> 「值不对」；② 块按 `resourcesPath/orchestrator/ui` 找 CSS，直接指仓库的 `output/ui` 是读不到的，
> 得先搭一个同布局的临时舞台目录。

### 第七种静默失败：单词级界面文案（两条对差通道都看不见）

片段级要 **≥3 词**、字面量级要 **≥2 词**，`regress.js` 的片段提取又只认句子——于是 `Settings` / `Projects` / `General` / `Missions` / `Theme` / `Reset` / `Width` / `Height` / `Availability` / `Browser` / `System` 这类**单词文案三条通道全都进不来**，漏了也不会有任何报错。

`tools/uipos_gap.js` 把这一步变成判据：**本版产物 − 上一版产物 − 登记表**，差集不为空就 exit 1（`update.sh` 的 6b 步报告，`release.sh` 的闸三拦发布）。

```bash
node tools/uipos_gap.js --bundle output/ui/assets/index-<hash>.js --prev dist/hanhua-pack-<上一版>.zip
node tools/uipos_gap.js --bundle output --prev dist/hanhua-pack-0.0.128.zip --limit 100
```

- 两侧都按同一口径解析 `uipos` 的输出（只取 `## 小节` 之后的「数字 + 制表符」行，`\t@ 上下文` 续行不算），否则差集会假报；
- 扣除的是 `intentional-english.json` 的 `uiStrings`（逐条写理由）；登记项死没死看的是**整串还在不在产物里**，与 `regress` 同一判据，**不是**「uipos 还看不看得见」（理由见下面「有意保留英文」一节）；
- 新增项在报告里**按形态自动分三桶**（`classifyItem`，纯形态判据不看语义）：
  - **能翻（补 dict.json）**：多词短语、首字母大写的单词标签（`Accepted` / `Mon` / `Somewhere`）；
  - **该登记（形态上多半不是文案）**：路径 / 资源名（`/api/byok/connections/…`、`….webp`、`localhost:3000`）、
    CSS 类名与选择器（`fpc fpc-- fpc--asset`、`.explorer, .explorer-header`）、命令行（`git init`）、
    代码与标识符（`getUser()` / `user?.name ??` / `mcpServers` / `'Guest'`）；
  - **存疑（人工定夺）**：含 `${…}` 的模板串（要补 `template` 还是登记，得看那一处）、
    带数字的标题式词（疑似模型名 / 版本号）、全大写缩写（分不出是术语还是标签）。
  分类**只是建议，不参与退出码**——分错只是白看一眼；`--flat` 回到分桶前的平铺清单（跨版 diff 两版报告时更顺手）。
  0.0.156 适配时 40 条新增就是这么从「逐条挑拣」变成「按桶复核」的（清单与实做记录见 `work/stale156.txt` 与 `CHANGELOG.md`）。

### 第八种静默失败：字面量在代码里当了值（翻掉就改行为）

词典按「完整字符串字面量」替换，分不清「给人看的标签」和「代码里的值」。典型例子是 `Cookies`：在 `browser-native.cjs` 里是文件选择器的筛选器名（该翻），在 `browser-import.cjs` 里却是磁盘上要找的目录名（`for (const suffix of ['Network/Cookies','Cookies'])` 之后再 `path.join`）——翻掉会让 Cookie 导入**静默找不到文件**，而构建全绿、界面正常，只有真去用那个功能才暴露。

`tools/lint_collisions.js` 把这条规则固定下来（`update.sh` 6b 步、`release.sh` 闸四），判据只有「这个字面量在 `electron/*.cjs` 里落在什么位置」：

- **文件系统调用参数**（`path.join(..., 'Cookies')`、`existsSync('x')`）→ 直接失败；
- **比较位置**（`x === 'Enabled'`、`.includes('KEY')`、`case 'KEY'`）→ 直接失败；
- **IPC / 事件通道名**（`ipcMain.handle('KEY')`、`.send('KEY')`）→ 直接失败；
- 提示项：同一字面量出现在 ≥2 个主进程文件里，附带**位置形态**标注（`数组元素` / `键值（name: …）` / `调用参数` / `其它`）——`Cookies` 那种「隔一个变量才进 `path.join`」的坑就在这里露头，看到「数组元素」就该追那个数组的去向。

只扫**字面量位置**是有意的：早期实现用 `includes()` 扫整个文件时，`discordEnabled` 里的子串会把词条 `Enabled` 误报出来。处置：从 `dict.json` 撤掉该词条、改写进 `patches/electron-*.patch`（只改该翻的那处），或把两处用法拆开。

#### 已知假阳性：`pattern` 短词 × 主进程的「超长字面量」

闸门对 `pattern` 词条是按「字面量**包含**该词」判的（它防的是 pattern 替换字面量内部子串那种情形），
而主进程文件没有压缩，片段提取器会把跨引号的代码配成**超长字面量**——`webContents.send('update-card', …)`
那一段正好落在里面，于是 0.0.148 的 Updates 节标题 `Version` 被报成「IPC / 事件通道名」。
判真假的办法是**实测**：`node tools/apply.js <原版 electron 文件>` 的替换次数为 0、与原文逐字节无差异，就是假阳性
（真阳性的样子相反：同一命令会改掉那处代码）。处置：把该词条从 `pattern` 挪到 `exact`
（`exact` 的判据是**整串相等**，不会被超长字面量沾到），或换成 `code` 整段片段；
**不要**为了让闸门变绿去放宽它。

### 第九种静默失败：补丁的「行号漂移」伪装成「上游改写」

上游在补丁覆盖区**之前**插几行，后面所有 hunk 的旧行号就整体偏了。`git apply` 的 hunk 搜索窗口受相邻 hunk 行号约束，偏移大的 hunk 会搜不到（报 `patch failed: electron/main.cjs:1500`），**即使那段上下文逐字节还在**。构建会以「补丁未干净套用」中止，但处置分几种：

- **行号漂移** → `node tools/reanchor_patch.js --all --write` 一条命令修好（只改 `@@` 头，补丁正文一个字节不动）；
- **上游改写**（上下文真的没了）→ 别手抄 hunk（`@@` 头上的计数与行首缩进错一处，报错位置还离真错处很远），用 `node tools/regen_patch.js --broken --write` 从补丁里既有的「英文行 → 中文行」映射重生成正文；
- **上游改的正是我们翻过的那一行** → 行号没漂、上下文也没「没了」，而是同一行的上下游两侧都变了：走**三方合并**（见下）；
- **上游在 hunk 中间插了新行** → 不是行号漂移，也不是「上下文整段没了」，而是 hunk 的 preimage 序列中间多了几行；译文本身仍然有效，用 `regen_patch.js` 重生成即可。

```bash
node tools/patch_preflight.js   # 分诊：逐 hunk 给结论与命令（update.sh 2b 步；build.sh 套不上时也会提示先跑它）
node tools/reanchor_patch.js --all --write      # 行号漂移
node tools/regen_patch.js --broken              # 上游改写 / hunk 中间插行——试运行，列出结论不写盘
node tools/regen_patch.js --broken --write      # 确认后写入（生成器自己跑 git apply --check 复验）
```

三方合并（上游改的正是我们翻过的那一行）：

```bash
# base  = 上一版英文原版
# ours  = 上一版英文原版 + 旧补丁（= 上一版汉化产物里那个文件）
# other = 本版英文原版
patch -p1 -i <旧补丁>            # 在 base 的副本上套一遍，得到 ours
git merge-file -p --diff3 ours base other > merged
```

冲突只会出现在「上游改的同一行就是本地翻过的那行」上，解决方式固定：**取上游的新写法、把中文回填进去**；上游在别处新增的行会自动合并进来，再按需补翻即可。最后 `diff -u` 重新生成补丁正文（**必须是 LF 行尾**：快照里的 `.cjs` 是 CRLF，但 `build.sh` / `patch_preflight` 打补丁前会把目标统一成 LF），跑一次 `node tools/patch_preflight.js` 确认全部干净套用。

两个必须记住的要点：

- **目标文本 = 快照 + 词典**（`reanchor_patch.js` 的 `buildMirror`）。`build.sh` 是先套词典再打补丁，所以补丁的上下文行里本来就可能带中文（`"Cancel"` 这类双引号文案早被词典替过）；直接比对英文原版会把这类 hunk 误报成「上游改写」。
- **空上下文行也是上下文**：补丁里跨过空行的 hunk，早期实现把空行当噪音丢掉，于是整段匹配不上。两个坑都写进了 `test_patch_preflight.js`。重锚定是**幂等**的：再跑一次不产生任何 diff。

### 有意保留英文：写进 `intentional-english.json`，别再敲 `--allow-english`

`--allow-english` 是一把**全放行**的逃生口：放行了什么、为什么放行，仓库里一行记录都没有；换机器或 CI 发布时很容易忘了加参数，或者为了让闸门变绿而随手放宽。现在逐条登记进仓库根的 `intentional-english.json`：

```json
{
  "fragments": [{ "text": "Failed to get offset for index:", "why": "react-window 内部 console.warn，非界面文案" }],
  "uiStrings": [{ "text": "DM Mono", "why": "字体名" }]
}
```

- `fragments` 给回归闸门（`regress.js`）用，`uiStrings` 给单词级差集（`uipos_gap.js`）用；上游对差（`upstreamdiff.js`）**两节都读**，登记过的单列一节带理由、不进待补翻计数（`--no-allow` 可临时忽略它看全清单）；
- 两条闸门都会把**理由一并打印**；登记项「还活着吗」只有**一条判据**，两处共用（`regress.js` 的 `presenceProbe`）：**这段英文（抹插值 + 折叠空白）还在不在本版产物里**。整串都没了（上游删掉 / 改写，或我们自己翻成了中文）才算死条目、提醒清理（不失败）；还在就说明仍有通道要它站岗。
  **不能拿某一条通道的集合去判**：`regress` 的片段集合带词数下限（片段级 ≥3 词）与 `CODEISH` 过滤，`uipos_gap` 只看界面位置，拿谁的集合算都会把别条通道登记的条目误报成死条目（0.0.140 → 0.0.147 那 5 条模型名 / 命令就是这么来的）。`regress` 这道提醒以前还挂在「已登记」分支里，常规全绿（本版没有任何新增片段）时根本不会跑，现在两处都是每次都查；
- `--allow-english` 保留为临时排障用。

### 「半截模板」词条：以未闭合的 `${…?` 结尾

Freebucks 那几句付费 / 钱包提示在外层模板里嵌了模板三元（`` `… plus your wallet.${fe?` ${fe.tooltip}`:""}` ``）。只翻固定段就得存一条**尾部没有闭合花括号**的键（`… plus your wallet.${fe?`），`apply.js` 把它连着后面那个反引号一起整段替换。这类键是特例：

- 译文必须**逐字节复现同一个半截尾巴**，否则替换后模板字符串直接断裂；
- 尾巴形态必须是 `${` + 非空 + 不含反引号 / 右花括号，否则 `remap.js` 捕获不了；
- 新增一条就得在 `lint_dict.js` 的 `TRUNCATED_TEMPLATE_ANCHORS` 里登记它的**英文骨架片段**（登记英文文字而不是变量名，minifier 改名后依然有效）。

`remap.js` 把它当普通模板迁移（版本适配第 1 步会自动跟进改名）；`lint_dict.js` 的 **E5** 会在违反上面任一条时硬报错，漏登记会直接卡住 CI 与发布。

### 改写译文时把 `${…}` 写残了（E6）

改译文最容易出的错不是翻错，是**把插值改坏了**：把 `${e.currentBranch??"a detached HEAD"}` 写成
`t.currentBranch??"游离的 HEAD"`，把 `${a?" 并结束当前会话":""}` 写成 `r?" 并结束当前会话":""`。
替换上去之后模板完整、JS 语法合法、**所有闸门全绿**，而用户看到的是界面上一串裸露的代码残骸。

`lint_dict.js` 的 **E6 模板残骸**专治这个：译文剔掉所有 `${…}` 之后，剩余文本若仍匹配
`?"` / `":` / `??` / `===` / `!==` / `=>` / `||` / `.length` 即判硬错误。这些词法在纯中文译文里
不可能合法出现（中文用全角标点与弯引号），命中就是插值的前缀或闭合被写丢了。

为什么 E3 拦不住：E3 只拦「译文里**多出**的 `${…}`」，且**数量少于 key 属正常**（中文吸收复数：
`${c===1?"":"s"}` 整段省略）。而残骸里连 `${` 都没有，E3 连统计都统计不到。`code` 分区跳过——
它本来就逐字钉代码片段，`?"删除":` 这类在 `${}` 内部不算残骸；半截模板键（键以未闭合的 `${条件?` 结尾）
同样跳过，它合法地留下 `${`。

**规则**：译文里凡是 `${…}` 里的字面量都要翻（`??"删除":""` 而不是 `??"":""`），插值的**前缀与闭合必须逐字照抄 key**，只改插值里面的文案。

## 词典结构（dict.json）

| 类型 | 作用 | 匹配方式 |
| --- | --- | --- |
| `exact` | 全局精确替换 | `"English"` |
| `template` | 反引号模板字面量 | `` `English ${...}` `` |
| `code` | 多 token 逐字片段（复数、属性名等） | 原样替换 |
| `pattern` | **仅界面属性位置**（含值里的三元分支与模板插值） | `children:"X"` / `label:"X"` / `title:"X"` / `placeholder:"X"` / `"data-tooltip":"X"` / `"aria-label":"X"` / `confirmLabel:"X"` / `actionLabel:"X"`，值位置也认 `confirmLabel:n="X"`、`label:cond?"X":cond2?"Y":"Z"` 与 `` aria-label:`${s?"X":"Y"} …` `` |
| `code`（全局一致替换型） | 必须**处处一起改**的界面标签常量 | 原样全局替换（比较位置也会改）；需在 `semantic_guard.js` 的 `CONSISTENT_LABELS` 登记中文值 |

应用顺序：`pattern` → `code` → `exact` → `template`，幂等（重复运行不会重复翻译）。

两条必须记住的规则：

- **界面文案翻，代码标识符不翻**。`exact` 是全局字符串替换，若某个词被用在代码位置（比较、switch、枚举自映射），翻它就会破坏运行时——`apply.js` 内置语义守卫，遇到这种会直接报错中止构建。短词、状态标签优先放 `pattern`（只作用于界面属性位置）。
- **词典 key 必须与 bundle 逐字节一致**（破折号 `—`、省略号 `…`、弯引号 `’` 都算）。以构建日志里的 MISSED 原文为准，别手抄或自行改写。
- **`pattern` 也会报 MISSED**：零命中的词条列进构建日志并中止构建，要么原文改了匹配形态、要么条目过期。

## 发布（可选，给别人用才需要）

```bash
bash tools/release.sh                  # 打包 output/ → dist/，并发布 GitHub Release
bash tools/release.sh --no-upload      # 只打包，打印手工上传步骤
bash tools/release.sh --force          # 同 packVersion 覆盖重发
bash tools/release.sh --allow-english  # 两道英文闸门都只报告不拦截
```

发布前有**两道英文闸门**，任一报出疑似漏翻都会中止发布（exit 1）：

- **闸门一 · 主进程**（`mainscan.js`）：英文原版的 `electron/*.cjs` vs 本次产物（见「第六种静默失败」）。原版取本机最新 `hanhua-backup-*`（与 `build.sh` 同源）；没有就退一步用快照仓库里那一版（`tools/pristine.js path`，免再解包）——`pristine.js import --from-release <targetVersion>` 取一份就有，所以「发布机没装过 Freebuff」不再等于「闸门白跑」。
- **闸门二 · 回归**（`regress.js`）：拉上一版已发布的包与本地产物对比（见「第三种静默失败」）；首次发布或离线取不到包时自动跳过。

两道闸门的原版与上一版包都找不到时，各自会**响亮地跳过**（打印 `!` 行）——那意味着这次发布并没有完整跑过闸门。发布成功后会把**本版英文原版快照**作为附加资产传到同一个 Release 上（`pristine.js publish`，失败只 WARN 不拦发布），下一台机器一条 `import --from-release` 就能开始对差。

产物：`hanhua-pack-<packVersion>.zip` + `pack-manifest.json`（含 SHA512），tag 为 `pack-v<packVersion>`。`packVersion` 在 `manifest.json` 里维护，跟随 `targetVersion`。需要 `gh auth login`。

- **同一 targetVersion 内的修正重发**（发完 0.0.103 又发现漏翻）：把 `packVersion` 升到 `0.0.103.1`（追加第四段），重新 `build.sh` 并发布即可。控制器比较新旧按**四段**，已装 0.0.103 的机器会被判定「有新包可应用」并自动拉取；而「这包装得上吗」的兼容性比对按**前三段**（第四段只是汉化包自己的修正标记），因此 `0.0.103.1` 与 Freebuff `0.0.103` 判定相容。
- **同号重发（`--force`）不升版本，已装机的机器不会自动更新**，只能在该机手动跑一次 `bash apply.sh`，仅适合回滚线上烂包这类应急场景。

## CI 里跑什么（`.github/workflows/ci.yml`）

两个 job，都能在 PR 上跑，都不碰专有产物：

- **`dict-lint`**：词典 lint + 22 个工具的合成夹具自测（`test_*.js`）+ 脚本语法冒烟。全部离线，只用仓库自己的夹具，所以网络抖动不会把纯自测带红。
- **`snapshot-gates`**：`bash tools/ci_gates.sh`——先取本版**英文原版快照**（`pristine.js import --from-release <targetVersion>`）与**上一版已发布包**（最新一个不是本版 `packVersion` 的 `pack-v*` Release），再跑 `release.sh` 的那**四道发布闸门**：闸一主进程漏翻（原版 `electron/` vs 镜像）、闸二回归闸门（上一版包 vs 镜像主 bundle）、闸三单词级界面文案（带 `--prev`）、闸四字面量占用（词典 × `electron/*.cjs`），外加补丁锚点预检。

  CI 里没有 `app.asar` / `ui` 产物，所以「本版产物」按 `build.sh` 的同一条链在前置步骤重建：主进程侧 = 快照 `electron/` + 词典（`apply.js`）+ 人工补丁（`git apply`，与 build 同一命令、同一目录口径），UI 侧 = 快照主 bundle + 词典。文本口径与真实产物一致——同一版实测跑出来与 `release.sh` 四道闸门的结论逐条相同。建镜像用 `reanchor_patch.js` 的 `buildMirror`（`patch_preflight` / `regen_patch` 判断补丁目标用的就是那一份），不会各家一个样。

  这些都不需要装 Freebuff、不需要解 `app.asar`，所以能提前到 PR 阶段。跳过一律打 `::warning::` 出声，且**不打印「全部通过」**（有闸门没给出结论时，「全部通过」就是假绿灯）：取不到上一版包时闸二标「未执行」、闸三退回「看全量」；连本版快照与替身都拿不到时才整批跳过并 rc 0。本地 `update.sh` 的 6b 步与 `release.sh` 的四道闸门用的是真实产物，那才是最终把关。

  **近似模式（版本刚 bump、本版原版还没发布时）**：本版快照谁都拿不到——本地没装过新版，Release 上还没有它的快照资产——而「本版要翻什么」恰恰在这种时候出现。脚本于是退一步：拿**上一版快照当替身**（快照仓库里低于 `targetVersion` 的最高一版；本地没有就从 Release 取上一版的 `pristine-<版本>.json.gz`，版本号按该 Release 的 `pack-manifest.json` 里 `targetVersion` 定，不拿 tag 后缀凑）重建产物，四道闸门照跑，但判据按替身能判定的范围分开，输出里逐条写明：

  - **能判定**：闸四字面量占用、镜像能否重建（词典 / 补丁 / 快照是否自洽）、补丁文件在不在——这三项与「词条对不对得上本版原文」无关，近似模式下照样 `::error::` 拦 CI；
  - **只能列差异**：闸一 / 闸二 / 闸三。本版词典相对上一版「下线 / 改写」的词条，在替身上那个位置仍是上一版的原文，于是必然出现在差异里；是上游真删了句（正常适配）还是我们误删（静默漏翻），替身上无从判断——那正是 `update.sh` 第 6 步对差报告要人看的东西。差异照打（CI 上还写进 job summary），但**不作判定、不拦 CI**；
  - **看不到**：本版**新增**的英文文案（替身里还没有这些句子）——这一部分由发布前的 `release.sh` 四道闸门（真实产物）把关。

  所以近似模式**不会**打印「全部通过」，而是「已判定 / 只列差异、未判定 / 看不到」三行。想手动预演一次下次 bump：`bash tools/ci_gates.sh --approx <上一版版本号>`（与 `--snapshot` 互斥：前者给本版原版，后者给上一版替身）。

  自测与排障都不联网：`--snapshot` / `--prev` / `--approx` 显式给快照、基线与替身（`--prev` 同 `regress.js` / `uipos_gap.js`，可给包 zip 也可给目录），`--no-baseline` 声明这次没有基线——`test_ci_gates.js` 就是靠它们在一台不联网的机器上跑完四道闸门与近似模式的假绿灯防线（含「近似模式不许放水」：替身上有词条被代码占用时闸四仍要 rc 1）。

触发路径：`dict.json` / `manifest.json` / `intentional-english.json` / `patches/**` / `tools/**` / `*.sh` / 工作流自身（改补丁或登记表也会触发，否则改了 `patches/` 白改）。

## 常见问题

- **装机是英文原版且没有 `hanhua-backup-*`**：`build.sh` 会直接用安装目录的英文原版作 pristine（首次构建的正常路径）。
- **`build.sh` 报「词典有 N 条未命中」**：官方改写了那些原文，按「出了新版本」补齐；确实可以接受缺口时用 `ALLOW_MISSED=1 bash build.sh`（未翻文案保持英文，功能无损）。
- **`build.sh` 报「替换次数为 0」**：词典没生效，几乎都是 bundle 换了名字 / 内容，重跑 `remap.js` 确认。
- **界面某处突然变英文**：多半是官方改写了那句文案，按 MISSED 清单补。
- **`build.sh` 报词典门禁错误（E5）**：「未登记的半截模板键」→ 把英文骨架片段补进 `lint_dict.js` 的 `TRUNCATED_TEMPLATE_ANCHORS`；「半截尾巴与 key 不一致」→ 译文的 `${…?` 尾巴必须与 key 逐字节相同；「只能出现在 template 分区」→ 半截键放错分区了。
- **界面直接显示出 JS 代码（`…当前在 t.currentBranch??"游离的 HEAD"` / `…使用 3r?" 并结束…`）**：译文把 `${…}` 的前缀或闭合写丢了，见上文「改写译文时把 `${…}` 写残了（E6）」。**先别发布**：修 `dict.json` 再 `bash build.sh`，这类破损过不了 E6 闸门。
- **上游新增 / 改写了一个主进程文件**：主进程文案多为单引号，词典够不着，历来靠 `patches/`。仿照 `patches/electron-renderer-health.cjs.patch` 新增一个 `patches/electron-*.patch`（用 `git diff --no-index --src-prefix= --dst-prefix=` 生成，上下文取 `sed 's/\r$//'` 后的 LF 形态），并在 `tools/postbuild.js` 的 `OPTIONAL_SENTINELS` 里登记一条译文哨兵（老版本 asar 里没这个文件，缺失只警告）。
- **`build.sh` 报「补丁未干净套用」/ UI 行为补丁 MISSED**：主进程按「第九种静默失败」重新生成 hunk；UI 行为补丁见「第五种静默失败」的维护办法。
- **回复卡住不结束（尤其刚崩过一次 orchestrator）**：见「第五种静默失败」，0.0.110.3 起已随包修掉。适配新版时若 `update.sh` 报「原版已复现不出缺陷」，说明上游可能自行修复了——那是补丁退场的信号，不是构建故障；想确认用 `node tools/ui_patch_status.js`。
- **界面提示「消息未发送 / 无法停止当前轮次 / 无法编辑消息 / 无法打开标签页: forbidden」**：本机 orchestrator 对**写操作**要求 `x-freebuff-launch-id` 头，对不上就 `403 {"error":"forbidden"}`，而渲染进程把这个令牌读一次就永久缓存，主进程却在每次 orchestrator 重启时换新（开新标签页也是一次写操作：`POST /api/threads`）。
  - **一键体检**：`node tools/forbidden_probe.js`（rc 0 = 没发现风险 / 1 = 有确凿风险 / 2 = 判不了），它回答两件事：装机 `app.asar` 里的 `electron/main.cjs` 有没有那条补丁、现在跑着的实例加载的是不是**换文件之前**那套代码（混合态）。
  - **手工复现**（应用正在跑时）：`curl -i -X POST http://127.0.0.1:<端口>/api/thread/x/rename -H 'content-type: application/json' -d '{"title":"probe"}'` → `403 {"error":"forbidden"}`；端口从 `netstat -ano | grep <bun.exe 的 PID>` 里找（`bun.exe` 才是 orchestrator）。
  - **最常见的触发条件是「换文件时应用正跑着」**：装机文件是运行中的进程按需从磁盘读的，而两侧时机不同——渲染侧每次加载 / 重载都重新读，主进程只在**进程启动时**读一次。于是热换会留下**混合态**：界面已是中文，主进程还跑着换文件之前那套。处置上要注意：**重载窗口只换渲染侧**，主进程仍是旧的，正确做法是彻底退出再启动。`apply.sh` 现在会挡住这种热换（与 `restore.sh` 同款闸门，`--force` 可强制）。
- **`remap.js` 报 AMBIGUOUS**：没自动迁移，需要人工把变量名抄对（`update.sh` 小结会点名条数）。译文的插值若改写了内部字符串常量（`${r.title||"新会话"}`），remap 按骨架对齐后只换标识符；对不上就拒绝写回、列为歧义，不会把词典改坏。**最常见的一类是同锚文本的两份拷贝**：上游从 0.0.134 起把侧栏那批组件在 bundle 里重复打了一份，两份插值**一致**时照旧自动迁移，两份**各自改了名**才落歧义——猜一份写下去，另一份会静静退回英文而 `build.sh` 照旧 `all keys matched`。
- **`npx -y @electron/asar extract-file <asar> package.json` 会就地覆盖当前目录的同名文件**：这个子命令是写进 **CWD**，不是打到 stdout。它曾把仓库根的 `package.json` 换成上游那份（`"type": "module"`），于是 `tools/*.js` 里的 `require` 全变成 `ReferenceError: require is not defined in ES module scope`——报错指向工具，根因却在一个文件被换了。要看 asar 里的单个文件就 `extract` 到临时目录再读：

  ```bash
  npx -y @electron/asar extract <app.asar> /tmp/asar-x && sed -n '1,20p' /tmp/asar-x/package.json
  ```

  被覆盖的文件若已入库，`git checkout -- <file>` 还原（别用 `git stash` / `git add -A`，容易连带丢掉别人的改动）。
