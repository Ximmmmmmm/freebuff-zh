# 服务器全自动更新部署

让你的服务器自动完成：**监测 Freebuff 新版本 → 下载官方安装包 → 解出原版 → 模板变量重映射 → 构建 → 校验 → 提交 → 发布 Release**。全程无需人工干预；有新增未翻译文案时自动中止并留下报告，绝不发半成品。

## 环境准备

一台 Linux 服务器（Debian/Ubuntu 为例），已安装：

```bash
sudo apt update
sudo apt install -y curl unzip p7zip-full git nodejs npm cron
sudo npm install -g n && sudo n 20        # Node 20+
gh auth login                             # gh CLI 登录（需 repo 权限）
```

克隆仓库：

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone https://github.com/Ximmmmmmm/freebuff-zh.git
sudo chown -R $USER:$USER /opt/freebuff-zh
cd freebuff-zh
```

## 手动跑一次（先验证再上 cron）

```bash
bash tools/autoupdate.sh
```

预期输出（版本相同时）：

```
[时间] 官方最新: 0.0.92 / 当前适配: 0.0.92
[时间] 版本未变，无需更新
```

版本不同时会走完整流水线：下载 → 校验 → 解包 → remap → 构建 → 扫描 → 提交 → 发布。

## 上 cron（每 30 分钟检查一次）

```bash
crontab -e
```

加一行：

```
*/30 * * * * cd /opt/freebuff-zh && bash tools/autoupdate.sh >> work/autoupdate.log 2>&1
```

日志在 `work/autoupdate.log`，流水线的每一步（下载了多少、校验是否通过、构建是否成功、发布到哪个 tag）都会带时间戳记录。

## 行为细节

### 版本探测

直接读官方 GitHub Releases API（`CodebuffAI/codebuff-community`），找 `freebuff-desktop-v*` 形式的 tag。`freebuff.com` 的下载直链本身就是 302 到这里，所以读 API 等价且更稳（还能顺带拿 SHA512）。

### 完整性校验

下载的安装包用官方 `latest.yml` 里的 SHA512（base64）转 hex 后与本地 `sha512sum` 比对，防止下载不完整或被劫持。

### 构建失败/有新文案时的行为

- `build.sh` 的防呆自检（`node --check`、词典全命中断言）失败 → 脚本中止，**不发布**
- 残留扫描发现 `MISSED`（新版改写过的文案词典没接住）→ 脚本回滚 `manifest.json`、退出码 2，**不发布**；报告留在 `work/update-<版本>.txt`，人工补翻 `dict.json` 后 `bash tools/autoupdate.sh --force` 重跑

### 发布

复用 `tools/release.sh`：打包 `output/` 为 `hanhua-pack-<版本>.zip` + `pack-manifest.json`（含 SHA512），发到 `pack-v<版本>` tag。控制器的「汉化包更新」每 30 分钟检查一次这个 Release，自动下载校验并提示用户「应用汉化」。

## 可选：通知

想在"自动中止需要人工"时收到通知，可在 cron 行后追加通知命令，例如 Server酱：

```
*/30 * * * * cd /opt/freebuff-zh && bash tools/autoupdate.sh >> work/autoupdate.log 2>&1 || curl -s "https://sctapi.ftqq.com/<你的KEY>.send?title=汉化包autoupdate需要人工&desp=$(tail -5 work/autoupdate.log | sed 's/$/%0A/g' | tr -d '\n')"
```

退出码非 0（通常是 2 = 有未翻译文案）就会触发通知。

## 常见问题

**Q: 服务器在国内，GitHub 下载慢/失败？**
A: `autoupdate.sh` 里的 `curl` 会走系统代理；给 cron 环境加 `https_proxy=http://127.0.0.1:7890`（按你的代理改）。

**Q: 7z 解不开新版安装包？**
A: 官方从 NSIS 换成其他打包格式时，`autoupdate.sh` 的目录兜底逻辑（全局 find app.asar / ui）会尝试适配；仍失败会在日志里明确报错，届时手动检查安装包结构。

**Q: 想强制重建当前版本？**
A: `bash tools/autoupdate.sh --force`（跳过版本短路，走完整流水线）。
