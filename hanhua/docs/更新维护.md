# 应用更新后的维护

Freebuff Desktop 自带 electron-updater，**自动更新会整体替换 `resources/app.asar` 与
`resources/orchestrator/ui/`，汉化随之丢失**。

## 一键迁移（推荐）

应用更新后跑一次：

```bash
bash tools/update.sh
```

它会自动完成模板变量重命名迁移（`remap.js`）、重新构建（含防呆自检）、残留扫描，
最后打印剩余人工事项——通常只剩「把新版改写过的文案补进 dict.json」这一步。
`tools/status.sh` 可随时查看装机/构建/备份状态，判断该走哪条路。

备份日积月赘时用 `tools/prune_backups.sh [份数] --yes` 清理。

## 手工流程（备用）

### 快速恢复（汉化内容未变时）

如果新版本只是修复性更新、界面文案没怎么变，直接用最近的备份重新应用即可：

```bash
bash apply.sh
```

> 若安装目录里的 `resources/hanhua-backup-*` 还是上一版的原版备份，且新版 UI 文案变化不大，
> 此命令几分钟内恢复中文。新版若改了文案，个别地方会退回英文（见下）。

## 完整重建（界面文案有变化时）

1. **拿到新版本的原版文件**：
   - 更新后安装目录下就是新版英文原版：`resources/app.asar` 与 `resources/orchestrator/ui/`
   - 或先跑一次 `bash apply.sh` 触发备份，再用
     `resources/hanhua-backup-<最新时间戳>/` 作为原版来源

2. **重新构建**：

   ```bash
   bash build.sh            # 自动用最近的 hanhua-backup-* 作为原版
   bash build.sh <新app.asar> <新ui目录>   # 或显式指定
   ```

3. **补翻新增文案**：`build.sh` 结束后，`tools/apply.js` 会打印未命中（MISSED）的词典项——
   新版改动过的字符串。按 `docs/汉化流程.md` 的流程扫描、补进 `dict.json`，再重新构建。

4. **安装**：`bash apply.sh`

## 经验法则

| 情况 | 做法 |
| --- | --- |
| 不知道现在啥状态 | `bash tools/status.sh` |
| 小版本修复，文案没变 | 直接 `bash apply.sh` |
| 文案有变 | `bash tools/update.sh`（或手工：`build.sh` 重建 + 补词典 + `apply.sh`） |
| 想退回英文 | `bash restore.sh` |
| 备份太多 | `bash tools/prune_backups.sh 3 --yes` |

## 路线图：自动恢复汉化

手工流程的痛点是"每次更新后要手动跑一次"。计划实现**启动时自检 + 自动恢复**：

- 主进程注入自检逻辑：启动时检查 `ui/index.html` 是否带汉化标记（如 `lang="zh-CN"`），
  缺失则从内置/持久副本自动恢复 `ui/` 与 `app.asar`，更新后首次启动即回到中文。
- 限制：自动更新会整体替换 `app.asar`，注入逻辑本身也会被换掉，因此需要配套
  "持久副本 + 外部触发"（如 Windows 计划任务）才能真正做到无人值守。
